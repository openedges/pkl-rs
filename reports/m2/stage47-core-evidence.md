# Stage47 core implementation evidence proposal

This package proposes publication of the frozen C06 implementation and its core checks. It does not commit or publish repository changes. The shared JSON/PCF renderer, directives, source-backed JSON annotations, collection join, semantic reference carriers, descriptor/activation slot history and compact diagnostic metadata remain the C06 code under review.

`summary-final.json` and `final-c06-binding.json` are authoritative addenda to the preserved preparation metadata. All 51,745 C06 source-map entries are bound. `source-bindings-final.json` connects exact bytes to pinned project/reference Git blobs, content-addressed source payloads, or six separately published report archives. Complete before/after maps and source-mode maps are retained. Seven early source versions remain hash-only and are explicitly scoped in `unresolved-source-bindings-final.json`; they do not affect C06. No historical source bytes were inferred.

The five required Rust commands passed on C06. The untouched upstream moduleOutput2 and pcfRenderer9 programs each matched the original Java CLI twice across complete stdout, stderr, exit and file channels. Captured commands, host/toolchains, raw logs, artifacts and bindings are preserved. Earlier failed workspace, stack, compile, clippy and setup runs remain failed evidence. The failed packaging preparation is also preserved.

Small-stack tests retain 256 KiB and the original depth limits. Lifecycle checks distinguish the eagerly initialized base graph from user graphs, retain stale-user-handle and close-zero assertions, and separately bound executable nodes. Three initialization-only polling loops changed to permit eager base setup; subsequent callbacks, deadlines and workload limits retain their recorded contract. Fixed/reference closure counts have source analysis but no per-node heap dump. The permanent frame-identity test consumes one Java power-assertions-enabled baseline of 240 observations under two real Rust instrumentation configurations, yielding 480 comparisons; it is not a Java on/off experiment.

Hint-only errors can allocate optional boxed details. No exact size, speed or memory improvement is claimed. Full scalar/String/constant-collection identity and evaluator-owned standard-module admission remain mandatory work. Singleton base/ref/test skip ModuleKey resolution but still require import-edge trust checks. The new whole selected regression, whole M2 and performance gates remain open.

Native renderer/API and actual platform acquisitions are independently owned and published. The older six C05 platform archives are referenced without nesting. Archive integrity does not establish language compatibility. Tar mode 0644 is packaging metadata; original source and artifact modes remain in their captured maps/inventories. Pinned Windows launcher checkout bytes and raw Git blobs are recorded separately without normalizing production or output bytes.

Only curated evidence staging is passed to `tools/evidence.py`. Exact source/cache exclusions were applied before traversing original evidence, and source payloads were selected by explicit map entries. The packaging wrapper records `create` and a separate `verify` invocation for every archive.
