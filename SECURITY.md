# Security Policy

## Supported Versions

`pkl-rs` tracks the Apple Pkl `0.32.0` baseline. Security fixes are applied to the latest `0.32.x` release line on `main`:

| Version | Supported |
| --- | --- |
| `0.32.x` (latest) | Yes |
| `< 0.32.0` | No |

## Reporting a Vulnerability

Please **do not** report security vulnerabilities through public GitHub issues.

Report vulnerabilities privately through GitHub Security Advisories:

- **Advisory URL**: https://github.com/openedges/pkl-rs/security/advisories/new

Include as much of the following as possible:

- Affected component (`pkl` CLI, `pkldoc`, `crates/pkl` [`pkl-lang`], `@openedges/pkl-wasm`, `@openedges/pkl-napi`, or `pkl-runtime`).
- Exact version, platform/OS/architecture, and runtime (`native`, `node`, browser engine).
- Minimal reproducible `.pkl` input, host configuration (`SecurityManager`, `rootDir`, `allowedModules`, `allowedResources`, HTTP/proxy settings), and observed vs. expected behavior.

## Security Model & Trust Boundaries

`pkl-rs` implements the Apple Pkl `0.32.0` security model and enforces memory safety across the workspace:

- **Memory safety**: The entire Rust workspace enforces `unsafe_code = "deny"` (`Cargo.toml`).
- **Module and resource confinement**: Access to modules (`--allowed-modules`) and resources (`--allowed-resources`) is governed by `SecurityManager` regex allowlists and optional `--root-dir` confinement, matching Apple Pkl `0.32.0`.
- **Sandboxed WebAssembly (`@openedges/pkl-wasm`)**: Runs without direct OS filesystem access, raw TCP/TLS sockets, external reader subprocesses, or disk caches. All I/O must be explicitly provided via `VirtualFileSystem` or custom async Host callbacks.
- **External readers & `pkl run`**: External module/resource readers (`--external-module-reader`, `--external-resource-reader`) and `pkl run` execute configured external programs/commands; only enable them for trusted inputs and configurations.
- **Package integrity**: `package:` and `projectpackage:` imports verify SHA-256 checksums against declared package metadata/lockfiles before evaluating archive contents.
- **Supply-chain verification**: Release archives and npm tarballs ship with `SHA256SUMS.txt` generated by [.github/workflows/release.yml](.github/workflows/release.yml). Always verify checksums before deploying prebuilt binaries.
